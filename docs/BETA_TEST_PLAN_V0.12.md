# v0.12.0 Beta 真实用户测试计划

## 目标

验证普通用户能在 Windows、macOS 与 Ubuntu 上完成 Wheel 安装和本地 CLI 分析，并确认正式报告符合中文七模块、PNG-only、原图保真、隐私与 Zero-token 规则。

测试只验证照片分析，不要求也不允许工具自动调色、套用 LUT、滤镜、美颜或进行生成式重绘。

## 测试规模

- 测试人数：3–5 人
- 每人照片：5–10 张
- 总测试量：30–50 张
- 分配时必须同时满足每人数量和总量目标，例如 5 人各测试 6–10 张。

## 操作系统覆盖

| 操作系统 | 最低覆盖 | 建议 Python |
|---|---:|---|
| Windows | 至少 1 人 | 3.10、3.12 或 3.13 |
| macOS | 至少 1 人 | 3.10、3.12 或 3.13 |
| Ubuntu | 至少 1 人 | 3.10、3.12 或 3.13 |

每个平台至少保留一份完整的安装、doctor、CLI 与输出检查记录。

## 照片类型覆盖

30–50 张照片的集合应覆盖：

- 单人人像
- 多人物
- 无人像
- 正脸
- 侧脸
- 强硬光
- 柔光
- 高调
- 低调
- 高饱和
- 低饱和
- ICC 图片
- 透明 PNG
- WebP
- 中文路径和文件名

同一张照片可以覆盖多个类型，但最终记录中必须标明其覆盖标签。JPG/JPEG、PNG 与 WebP 都是输入格式；正式报告仍只能输出 PNG 和 JSON。

## 隐私与测试素材

- 测试照片保留在测试者本机，不上传到仓库、公开 Issue、CI 或共享网盘。
- 不收集真实照片作为公开 Golden Dataset，也不提交私人 Ground Truth 或人像验收图。
- 公开反馈不得附带 API Key、Token、EXIF GPS、真实姓名、精确地址或其他个人数据。
- 如需提交问题，只附脱敏后的 `analysis.json`、`color-palette-doctor` 输出和错误日志；提交前移除本地绝对路径、文件哈希及可识别个人的信息。

## 测试前准备

1. 从候选 Release Asset 或指定 CI Artifact 获取 Wheel，并记录文件名和 SHA-256。
2. 创建全新虚拟环境并安装 Wheel。
3. 运行 `python -m pip check`。
4. 运行 `color-palette --help` 与 `color-palette-doctor`。
5. 记录操作系统、系统版本、CPU 架构、Python 版本、工具版本、OpenCV 版本及字体诊断结果。
6. 对每张输入照片计算分析前 SHA-256，用于确认程序未改写原文件。

## 单张照片测试步骤

```bash
color-palette "照片路径/中文文件名.jpg" --output "测试输出/中文目录"
```

每次运行后：

1. 确认 CLI 正常退出，或记录完整错误日志。
2. 确认只生成 `{filename}_analysis.json` 与 `{filename}_color_report.png`。
3. 递归检查输出目录，确认 JPG/JPEG 数量为 0。
4. 确认 PNG 尺寸为 1600×1200、比例为 4:3。
5. 确认报告使用中文固定七模块，且没有用户可见的研发术语。
6. 再次计算输入照片 SHA-256，确认与分析前一致。
7. 单人人像检查两张同尺寸 1:1 原始像素肤色取样截图；多人检查肤色不合并；置信度不足时检查显示“样本不足”。
8. 确认报告原图区域没有锚点圆圈、数字、人脸框或关键点。

## 每张照片记录字段

| 字段 | 记录要求 |
|---|---|
| 测试编号 | 使用不含个人身份信息的编号 |
| 照片类型 | 从覆盖类型中选择，可多选 |
| 安装是否成功 | 是 / 否；失败时关联错误日志 |
| CLI 是否成功 | 是 / 否；记录退出码 |
| PNG 是否生成 | 是 / 否；记录尺寸 |
| JSON 是否生成 | 是 / 否；记录 Schema 校验结果 |
| 是否错误生成 JPG | 是 / 否；期望为“否” |
| 原图是否发生色彩变化 | 是 / 否；同时记录分析前后 SHA-256 是否一致 |
| 影调判断 | 记录报告结论及用户是否认可 |
| 明暗关系 | 记录低 / 中 / 高及用户意见 |
| 色彩饱和度 | 记录低 / 中 / 高及用户意见 |
| 白平衡 | 记录正式结论或可信中性色不足 |
| 肤色锚点 | 记录单人 / 多人不合并 / 样本不足及截图情况 |
| 素材特效 | 记录报告结论及用户意见 |
| 光线构成 | 分别记录光源、光质、光比及用户意见 |
| 错误日志 | 脱敏后保存；成功时填“无” |
| 用户意见 | 记录可读性、准确性和操作体验反馈 |

## Beta 通过标准

- Windows、macOS、Ubuntu 均有成功安装与 CLI 记录。
- 汇总样本达到 30–50 张，并覆盖全部指定照片类型。
- 每次成功分析均生成且只生成 PNG + JSON，JPG/JPEG 输出数量为 0。
- 输入文件分析前后 SHA-256 一致，没有发生原图写入或色彩调整。
- 正式 PNG 为 1600×1200、4:3，中文七模块完整且可读。
- 私人照片、私人 Ground Truth、字体、密钥与 Token 均未进入仓库或公开反馈。
- 所有失败均能提供脱敏错误日志，并可区分安装问题、格式问题、人脸后端降级或报告渲染问题。

## 汇总与后续

按操作系统、输入格式、照片类型和失败类别汇总结果。算法判断争议只能作为候选反馈，不得未经人工复核直接写入公开 Golden Dataset。阻塞性安装、隐私、原图保真、输出协议或中文可读性问题必须在正式发布前修复；非阻塞识别偏差进入后续版本任务。
